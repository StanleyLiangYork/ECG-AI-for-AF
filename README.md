# ECG-AI-for-AF
This repository contains the Python scripts CSV files to replicate the figures for the systematic review *Knowledge Graphs and Language Models for
ECG-Based Atrial Fibrillation Analysis: A Systematic Review*. <p>
Authors: Zhaohui Liang, Sivaramakrishnan Rajaraman, Niccolo Marini, Matthew Song,  Zhiyun Xue, and Sameer Antani <p>

Every figure in the manuscript and its appendices is generated by one of the five scripts
in this folder, from a CSV held in the same folder. No figure is drawn by hand, and no
data value is written into the plotting code. Cloning this folder and running the commands
below reproduces all six figures exactly.

## Contents

| Script | Figure | Input CSV |
|---|---|---|
| `make_traffic_light_plot.py` | Appendix D — QUADAS-3 traffic light | `quadas3_traffic_light_plot_data_integrate.csv` |
| `make_traffic_light_plot.py --tool probast` | Appendix E — PROBAST+AI traffic light | `probast_ai_traffic_light_plot_data_integrate.csv` |
| `make_grade_certainty_plot.py` | Fig. 5 / Appendix F — GRADE certainty grid | `grade_evidence_profile_integrate.csv`, `grade_outcome_short_labels.csv` |
| `make_forest_plot.py` | Fig. 3 / Appendix G Fig. G1 — point estimates | `table1_diagnostic_accuracy.csv`, `table2_auroc_discrimination.csv` |
| `make_paradigm_matrix.py` | Fig. 4 / Appendix G Fig. G2 — paradigm × task matrix | `paradigm_task_matrix_data.csv` |
| `make_reporting_matrix.py` | Appendix G Fig. G3 — AI/KG reporting practices | `ai_kg_reporting_matrix_data.csv` |

`table3_benchmark_segment_level.csv` supplies Table G3 in Appendix G and has no figure.
`grade_traffic_light_plot_data_integrate.csv` is a study-level GRADE export retained for the
Appendix F workbook; see the warning under *GRADE certainty grid* below.

## Requirements

Python 3.9 or later with `matplotlib`. Nothing else is needed; every script uses only
`matplotlib` and the standard library.

    pip install matplotlib

Developed and tested on Python 3.10 with matplotlib 3.10.

## Reproduce every figure

Run from this directory.

    # Appendix D — QUADAS-3, 9 diagnostic-accuracy estimates
    python3 make_traffic_light_plot.py \
      quadas3_traffic_light_plot_data_integrate.csv \
      -o quadas3_traffic_light_plot.png

    # Appendix E — PROBAST+AI, 3 models as development and evaluation rows
    python3 make_traffic_light_plot.py \
      probast_ai_traffic_light_plot_data_integrate.csv \
      --tool probast \
      -o probast_ai_traffic_light_plot.png

    # Fig. 5 / Appendix F — GRADE, 8 outcome-level bodies of evidence
    python3 make_grade_certainty_plot.py \
      grade_evidence_profile_integrate.csv \
      --labels grade_outcome_short_labels.csv \
      -o grade_certainty_column.png

    # Fig. 3 / Fig. G1 — point estimates, two panels
    python3 make_forest_plot.py \
      --accuracy table1_diagnostic_accuracy.csv \
      --auroc table2_auroc_discrimination.csv \
      -o forest_point_estimates.png

    # Fig. 4 / Fig. G2 — paradigm by clinical task
    python3 make_paradigm_matrix.py \
      paradigm_task_matrix_data.csv \
      -o paradigm_task_matrix.png

    # Fig. G3 — AI and knowledge-graph reporting practices
    python3 make_reporting_matrix.py \
      ai_kg_reporting_matrix_data.csv \
      -o ai_kg_reporting_matrix.png

Each run writes a `.png` and a matching vector `.pdf`.

## The scripts

### Risk-of-bias traffic lights — `make_traffic_light_plot.py`

    python3 make_traffic_light_plot.py INPUT.csv [-o OUT.png] [--tool quadas3|probast]
                                       [--title TEXT] [--subtitle TEXT] [--dpi 300]

One row per estimate for QUADAS-3, or per model for PROBAST+AI. Row order in the CSV is
preserved. Cell values may be `low`, `high`, `insufficient_information`, `unclear`,
`not_applicable`, or empty.

PROBAST+AI rates model development separately from model evaluation, so each model in the
CSV produces two plotted rows. Columns carry `development_*` and `evaluation_*` prefixes
with `_quality` / `_risk_of_bias` and `_applicability` suffixes.

### GRADE certainty grid — `make_grade_certainty_plot.py`

    python3 make_grade_certainty_plot.py PROFILE.csv [-o OUT.png] [--labels LABELS.csv]
                                         [--title TEXT] [--note TEXT] [--dpi 600] [--no-key]

One row per outcome-level body of evidence. Required columns are `outcome_id`, `outcome`,
`risk_of_bias`, `inconsistency`, `indirectness`, `imprecision`, `publication_bias` and
`final_certainty`. Domain values may be `not_serious`, `serious`, `very_serious`,
`not_estimable`, `not_assessable` or `no_evidence`.

`--labels` takes a two-column CSV (`outcome_id`, `short_label`) for the key beneath the
grid. Those short labels are editorial, which is why they are a separate file rather than
part of the evidence profile. Without `--labels` the full `outcome` text is used.

**Input level matters.** This script requires the outcome-level *evidence profile*. It must
not be given the study-level file `grade_traffic_light_plot_data_integrate.csv`, which is
also in this folder. GRADE certainty is a property of a body of evidence assembled per
outcome and cannot be derived from a single study, so every row of the study-level file
carries `valid_final_grade_unit = false` and `overall_certainty = cannot_determine`. The
script detects that file and exits with an explanatory error rather than drawing a
misleading figure.

### Point estimates — `make_forest_plot.py`

    python3 make_forest_plot.py --accuracy TABLE1.csv --auroc TABLE2.csv
                                [-o OUT.png] [--dpi 300]

Panel A shows paired sensitivity and specificity at patient or case level. Panel B shows
model discrimination. **Nothing is pooled.** The targets, index tests, units of analysis and
datasets differ, and several studies reuse the same public benchmark databases, so the
panels place estimates side by side for comparison only.

A row whose `metric` is not a plain AUROC, such as a macro-average over several rhythm
labels, is drawn grey and labelled as not AF-specific, because it does not estimate
AF-specific discrimination and is not comparable with the other points.

### Paradigm × task matrix — `make_paradigm_matrix.py`

    python3 make_paradigm_matrix.py INPUT.csv [-o OUT.png] [--title TEXT] [--dpi 300]

One row per study, with columns `study_label`, `paradigm`, `task`, `unit` and
`external_validation`. Marker colour gives the unit of analysis (`patient`, `record`,
`segment`, or `none` for a study with no AF-specific estimate). A star marks external or
cross-dataset validation.

Row and column order follow the `PARADIGMS` and `TASKS` lists in the script. A value not
found in those lists is appended rather than dropped, so no study can silently disappear
from the figure.

### Reporting-practice matrix — `make_reporting_matrix.py`

    python3 make_reporting_matrix.py INPUT.csv [-o OUT.png] [--title TEXT]
                                     [--note TEXT] [--dpi 300]

The first CSV column holds the study label; every remaining column becomes a practice
column. Cell values are mapped to four classes by `VALUE_CLASS` in the script: adequate
(green), partial (amber), absent (red) and not applicable (grey). A value the mapping does
not recognise is drawn as absent **and** reported on stderr, so a new vocabulary term
cannot enter the figure unnoticed.

The matrix is descriptive. No cell feeds a QUADAS-3, PROBAST+AI or GRADE judgment.

## Editorial judgments, and where they live

Two figures depend on groupings that are not fields extracted from the source papers. Both
are recorded explicitly so a reader can inspect or revise them.

- **Paradigm and task assignments** (`paradigm_task_matrix_data.csv`). Each study is placed
  in one paradigm and one clinical task. Several studies could reasonably occupy more than
  one cell. The assignments are in the CSV, not in the plotting code.
- **Reporting classes** (`VALUE_CLASS` in `make_reporting_matrix.py`). Turning recorded
  wording into four classes is a judgment: a study reporting version, prompt and temperature
  counts as adequate, while one reporting version and prompt counts as partial. The mapping
  is a single table at the top of the script.

## Data provenance

The CSVs here are copies of the integrated consensus datasets produced during the review.
Risk-of-bias and certainty files come from two independent reviewers whose judgments were
reconciled; all records reached consensus. Files are kept alongside the scripts so that each
figure reproduces without reaching outside this folder.
